# Новий FSD-слайс

Архітектура — розділ 4 `CLAUDE.md`.

## 1. Обери шар

| Шар         | Що там                                          | Приклад                        |
| ----------- | ----------------------------------------------- | ------------------------------ |
| `pages/`    | екран маршруту, збирає віджети                  | `today`                        |
| `widgets/`  | самостійний блок екрана з кількох фіч/сутностей | `day-summary`                  |
| `features/` | **дія користувача**, мутація                    | `log-weight`, `answer-clarify` |
| `entities/` | **дані домену**: читання, відображення          | `entry`, `recipe`              |
| `shared/`   | без знання домену                               | `ui`, `lib`, `api`             |

Дієслово → feature, іменник → entity. Сумніваєшся — спитай до створення.

## 2. Структура (kebab-case)

```
features/<name>/
  ui/            — компоненти слайсу
  model/         — хуки, стан (TanStack Query / Zustand), zod-схеми форм
  api/           — запити (через shared/api)
  lib/           — чисті функції
  index.ts       — публічний API: лише те, що потрібно назовні
```

Порожні папки не створюй — лише ті, що потрібні зараз.

## 3. Межі

- Імпорт лише вниз: page → widget → feature → entity → shared.
- Feature не імпортує з іншої feature. Потрібна спільна логіка — вона в entity або shared.
- Ззовні — тільки через `index.ts`, ніколи `features/x/ui/Thing`.
- Похідний стан — під час рендера, не `useEffect`.

## 4. Стани

Кожен слайс, що вантажить дані, має завантаження (Skeleton / Loader), порожньо, помилку з повтором — розділ 12 `CLAUDE.md`.
Вигляд станів — скіл `screen-from-mockup`, порожньо — `add-empty-state`.
