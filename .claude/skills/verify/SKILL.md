# Самоперевірка задачі

Мета — щоб користувач отримав робочий результат, а не «має працювати». Проходь лише ті розділи, яких торкалася задача, але розділи 1 і 5 — завжди.

Правило: пункт вважається перевіреним, лише якщо ти реально запустив команду чи відкрив сторінку й побачив результат. Інакше в звіті — «не перевірено» з причиною.

## 1. Базова перевірка (завжди)

```bash
pnpm lint
pnpm typecheck
pnpm test
```

Усе має бути зеленим. Червоне — виправ і запусти знову. Не вимикай правила лінтера й не пиши `// @ts-ignore`, щоб пройти перевірку.

## 2. Бекенд (якщо змінювався `apps/api` або `packages/shared`)

1. **Схема й міграції** (якщо змінювалась `schema.prisma`):
   - `pnpm --filter api prisma validate`
   - `pnpm --filter api prisma migrate dev` — міграція створена й застосована, назва осмислена
   - нові поля мають розумні дефолти; записи користувача мають `deletedAt` і `userId`
2. **Запуск:** `pnpm --filter api dev` стартує без помилок і попереджень у лозі.
3. **Ендпоінти — реальні запити** (curl або HTTP-клієнт) для кожного нового чи зміненого ендпоінту:
   - головний сценарій → правильні дані у форматі `{ data }` або `{ data, meta }`
   - невалідні дані → `422` з `VALIDATION_ERROR` і полями в `details.fields`
   - неіснуючий `:id` → `404` з власним `errorCode`
   - без токена → `401`
   - **IDOR:** другим тестовим користувачем спробуй прочитати й змінити дані першого → має бути `404`/`403`, дані не віддаються
   - для списків — пагінація й `meta`
4. **Soft delete:** видалений запис не з'являється у вибірках.
5. **Ліміти:** для нових auth-ендпоінтів чи ендпоінтів з AI спрацьовує throttler.
6. **Логи:** у виводі сервера немає паролів, токенів, ключів, тексту повідомлень, ваги чи записів їжі. Помилки логуються з контекстом.
7. **Тести:** для нової логіки є тест на головний сценарій і хоча б один edge case. Немає — запусти субагента **`test-writer`** і додай його результат у звіт; знайдені ним баги виправ і перевір заново.

## 3. Фронтенд (якщо змінювався `apps/web`)

1. **Запуск:** `pnpm dev`, сторінка відкривається без помилок у терміналі.
2. **Браузер — субагент `ui-checker`** (якщо змінився вигляд): передай йому змінені екрани й стани. Він робить скриншоти на 390 px, звіряє з `design/screenshots/` і макетом, перевіряє стани (skeleton, порожній, помилка, успіх), консоль і a11y. Розбіжності з його звіту виправ і за потреби запусти ще раз.
   - Головний сценарій кліками (ввести, надіслати, відредагувати, скасувати) пройди сам.
3. **Консоль браузера:** без помилок і попереджень React (ключі, hydration, неконтрольовані інпути).
4. **Мережа:** запити йдуть на `/api/v1/...`, без зайвих повторних запитів, помилки показуються користувачу.
5. **Тексти:** жодного сирого ключа i18n на екрані (`chat.composer.placeholder`) і жодного хардкоду в коді. Якщо змінювались тексти чи `uk.json` — субагент **`copy-i18n`** (хардкод, ключі, тон).
6. **Accessibility:** усі кнопки досяжні з клавіатури (Tab), видно фокус, тап-цілі ≥ 44 px, іконкові кнопки мають `aria-label`.
7. **Адаптивність:** глянь також 768 px і 1280 px — нічого не ламається й не виходить за екран.

## 4. AI (якщо змінювались промпт, інструменти, модель чи AI-модуль)

1. `pnpm --filter ai-eval eval` — середня похибка не погіршилась порівняно з попереднім рядком у `PROMPT_CHANGELOG.md`. Результат передай субагенту **`ai-eval-analyst`**: він порівняє з попередньою версією, назве регресії по кейсах і дасть готовий рядок для changelog.
2. Додай рядок у `PROMPT_CHANGELOG.md` (від `ai-eval-analyst`): дата, що змінено, модель, похибка калорій і білка, токени на запит.
3. Живий тест у чаті (або через ендпоінт) на кількох фразах:
   - проста: «3 варені яйця і 100 г гречки» → записи, суми правильні
   - з уточненням: «тарілка супу» → питання про вагу/склад, але запис з оцінкою є
   - фото етикетки (якщо зачіпали фото) → `source: label`
   - «з'їв камінь» → `not_food`, нічого не записано
4. Відповідь пройшла zod-валідацію; некоректні значення відкинуті, а не збережені.
5. У лозі є токени й вартість запиту, але немає тексту повідомлення.

## 5. Самоперегляд diff (завжди)

Запусти `git diff` (і `git status` для нових файлів) і пройдися по кожному файлу:

- [ ] нічого зайвого: зміни лише в межах задачі, без «заодно відрефакторив»
- [ ] немає `any`, `@ts-ignore`, `console.log`, debug-коду, закоментованого коду, невикористаних імпортів
- [ ] стрілкові функції, guard clauses, імена за конвенцією
- [ ] немає хардкоду рядків UI; немає довільних значень Tailwind (`bg-[#...]`, `p-[13px]`)
- [ ] нові слайси FSD мають `index.ts`; немає імпортів між features
- [ ] бекенд: repository без бізнес-логіки, доступ між модулями лише через сервіси, помилки через `AppException`
- [ ] немає секретів, `.env` чи реальних особистих даних у змінах
- [ ] не дубльовано наявний компонент, хук, утиліту чи repository
- [ ] файли не розрослися понад ~200 рядків без причини

## 6. Звіт користувачу

Завершуй задачу коротким звітом українською в такому форматі:

```
## Готово: <назва задачі>

**Що зроблено**
- ...

**Як перевірено**
- pnpm lint / typecheck / test — ✅
- <ендпоінт або екран> — ✅ <що саме перевірив>
- Скриншот: <шлях або опис>

**Не перевірено**
- <що і чому> (або «—»)

**Ризики й наступні кроки**
- ...

Коміт не зроблено — чекаю команди.
```
