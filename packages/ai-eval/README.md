# ai-eval

Перевірка якості розбору їжі: той самий запит, промпт і валідація, що й у бекенді (`packages/shared/src/ai`).

```bash
pnpm --filter ai-eval eval                      # модель з AI_MODEL (apps/api/.env)
pnpm --filter ai-eval eval --estimate --models a,b   # оцінка вартості без запитів до моделей
pnpm --filter ai-eval eval --models a,b,c       # порівняння моделей
pnpm --filter ai-eval eval --only banana-piece,clarify-soup --max-cost 0.5
pnpm --filter ai-eval eval --reasoning minimal   # режим роздумів (за замовчуванням — як у бекенді)
```

Ключ і модель беруться з `apps/api/.env`. `--max-cost` (за замовчуванням $3) зупиняє прогін. Повні результати — у `results/` (у `.gitignore`).

## Метрики

- **ккал і білок** — % від еталону, окремо для **точних** (етикетки, зважені продукти, USDA) і **діапазонних** (страви «на око»: усередині діапазону — 0 %, поза ним — до найближчої межі). Мінімальна база — 50 ккал / 5 г білка, щоб малі значення не роздували похибку.
- **категорії** — частка очікуваних категорій, знайдених серед записаних позицій (окремо від ккал: категорія впливає лише на іконку).
- **рішення** — `log` / `clarify` / `not_food` / `reply` (+ `log_or_clarify`, коли обидва допустимі; для `reply` — обов'язкові факти, напр. залишок ккал).
- повтори, збої валідації, обрізані відповіді (`OUTPUT_TRUNCATED`), відповіді без інструмента, $ і токени (з cached) на запит, латентність p50/p95.
- **уточнення:** для кейсів з очікуваним `clarify` — причина, якщо питання не дійшло: модель не спитала / спитала, але нижче порогу / позиція покрита збереженим продуктом (`expect.clarifyAbout`, без уточнень у тексті). Окремий рядок «рішення з урахуванням пам'яті» вважає останній випадок правильним `log`.

## Свої кейси (`data/private/`)

Реальні прийоми їжі не комітяться: `data/private/` у `.gitignore`, eval підхоплює файли, якщо вони є.

- `*.cases.json` — масив кейсів у тому ж форматі, що й у `src/cases` (`id`, `text`, `expect`, `reference`);
- `*.foods.json` — збережені продукти (MyFood): `name`, `aliases`, `per100g { kcal, protein, fat, carbs }`, `pieceGrams`, `defaultGrams`, `category`. Модель бачить ті, що згадані в тексті кейсу, як `m1…`, а цифри записів з пам'яті eval перераховує з `per100g`, як бекенд.

```json
[
	{
		"id": "my-breakfast",
		"text": "вівсянка 60 г на воді і банан",
		"expect": {
			"decision": "log",
			"kcal": { "min": 300, "max": 360 },
			"categories": ["porridge", "banana"]
		},
		"reference": "зважено вдома, етикетка вівсянки 366 ккал/100 г"
	}
]
```

`--set private` — прогін лише приватних кейсів, `--set repo` — лише синтетичних. У терміналі — агреговані метрики й id кейсів, тексти не друкуються.

### Кейси з фото

Фото лежать поруч, у `data/private/` (наприклад `data/private/photos/`), і теж не комітяться. Кейс отримує `image` — шлях відносно `data/private/` (`.jpg`, `.png` або `.webp`); `text` тоді необов'язковий. Фото йде в модель як є — поклади вже таке, яке надіслав би застосунок (довша сторона до 1568 px, до 1 МБ JPEG), інакше eval лише попередить. У `results/` потрапляють id і цифри, самого фото там немає.

```json
[
	{
		"id": "label-skyr",
		"image": "photos/skyr-label.jpg",
		"text": "150 г",
		"expect": {
			"decision": "log",
			"kcal": { "exact": 96 },
			"protein": { "exact": 16.5 },
			"sources": ["LABEL"],
			"categories": ["yogurt"]
		},
		"reference": "етикетка: 64 ккал / 11 г білка на 100 г"
	},
	{
		"id": "plate-chicken",
		"image": "photos/plate-1.jpg",
		"expect": {
			"decision": "clarify",
			"kcal": { "min": 450, "max": 650 },
			"sources": ["ESTIMATE"]
		},
		"reference": "курка ~150 г, гречка ~200 г, салат; питання про олію"
	},
	{
		"id": "not-food-keyboard",
		"image": "photos/keyboard.jpg",
		"expect": { "decision": "photo_unusable" },
		"reference": "немає їжі"
	}
]
```

- `expect.sources` — кожна записана позиція має нести одне з цих джерел (етикетка → `LABEL`, страва «на око» → `ESTIMATE`); у таблиці це колонка «джерела».
- `expect.decision: "photo_unusable"` — не їжа або нечитабельна етикетка: модель має попросити перефотографувати, нічого не записавши.
- `--estimate` рахує картинку за патчами 28×28 px (1568×1176 ≈ 2 350 токенів), а не за довжиною base64.

Мінімальний набір для етапу фото: 3 етикетки (з вагою нетто; без ваги + текст «150 г»; без нічого → `clarify`), 3 страви (тарілка з олією → `clarify`; проста страва; кілька позицій), 2 «не їжа / розмито» → `photo_unusable`.

Після зміни промпту, інструментів чи моделі — прогін і рядок у `PROMPT_CHANGELOG.md` у корені.
