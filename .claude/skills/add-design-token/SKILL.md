# Новий токен

Токени: `apps/web/src/shared/ui/theme/tokens.css` (Tailwind v4 `@theme`) + пояснення «коли вживати» в `design/tokens/tokens.json`.

## 0. Майже завжди токен уже є

Перед додаванням знайди найближчий у `tokens.css`. Різниця в 1–2px чи кілька відтінків — не привід для нового токена: бери наявний.
Новий токен — коли з'являється нова **роль** (новий тип стану, новий вид поверхні), а не нове значення.

## 1. Назва — за роллю

`--color-<роль>`: `--color-over`, `--color-food-dairy`. Не за кольором (`--color-orange-2` — ні).
Простори Tailwind v4: `--color-*`, `--radius-*`, `--shadow-*`, `--text-*`, `--font-*`, `--ease-*`. Тривалості й градієнти — у `:root` / `@utility`, як наявні.

## 2. Значення

- Колір — з палітри «Хом'як» або її відтінок; теплий, не холодний сірий/м'ятний.
- **Контраст:** текст на поверхні ≥ 4.5:1, великий текст та іконки ≥ 3:1. Порахуй (будь-який калькулятор WCAG або скриптом) і впиши в звіт.
- `success` — лише для успіху й даних, `danger` — лише для помилок. Нова роль не дублює ці.

## 3. Де записати

1. `tokens.css` — з коментарем «для чого».
2. `design/tokens/tokens.json` — `value` + `use` (дозволений виняток для `design/`).
3. Якщо токен стосується описаного компонента — рядок у `design/docs/components.md`.

## Готово, коли

- [ ] перевірено, що наявного не досить
- [ ] назва за роллю, контраст пораховано
- [ ] записано в `tokens.css` і `tokens.json`; клас працює (`bg-…`, `text-…`)
- [ ] звіт за `/verify`
