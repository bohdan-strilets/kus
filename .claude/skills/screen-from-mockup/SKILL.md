# Екран за макетом

Еталон — `design/mockups/<екран>.html` і `design/screenshots/<екран>.png`. Мета — повторити, а не покращити.

## 1. Знайди макети

`design/docs/screens.md`: маршрут → екран → **усі стани** (порожньо, помилка, завантаження, перебір…).
Реалізуєш екран — реалізуй і його стани з макетів, а не лише основний.

## 2. Прочитай HTML макета

Відкрий `.html` повністю: там точні px, кольори, тексти. Випиши:

- структуру блоків зверху вниз;
- тексти (дослівно → у i18n);
- для кожного елемента — який компонент Рівня 0 або предметний компонент його покриває (`design/docs/components.md`).

Кольори з макета переводь у токени (`#B9521A` → `primary`). Hex, якого немає в токенах, — сигнал запустити `add-design-token` або взяти найближчий.

## 3. Збери з наявного

- Спершу наявні компоненти. Новий компонент — через скіл `new-ui-component`, якщо він повторюється 2+ рази.
- Іконки — лише `<Icon>`; бракує — скіл `add-icon`. Страви — `<FoodIcon>`. Маскот — `<Hamster>` / `<HamsterHead>`.
- Рух — пресети з `shared/lib/motion` за `design/docs/motion.md`; звук — `playSound` за `design/docs/sounds.md`.
- Дані — сід-дані з кінця `screens.md` (2 200 ккал, Б 140 / В 225 / Ж 80 …), щоб порівнювати з макетом цифра в цифру.

## 4. Звір

1. Скриншот застосунку на 390×844 (DevTools) з тими самими даними.
2. Поклади поруч з `design/screenshots/<екран>.png` і перелічи розбіжності: відступи (px), розміри, кольори, тексти, порядок.
3. Виправ і повтори, поки розбіжності не стануть лише свідомими (динамічні дані, системні шрифти) — їх назви у звіті.

## Не роби

- Не додавай кнопок, пунктів, станів, яких немає в макеті. Бракує — запитай.
- Не міняй тексти «на краще», не прибирай деталі, що здаються зайвими.
- Не реалізуй темну тему.

## Готово, коли

- [ ] основний екран і всі його стани з `screens.md`
- [ ] скриншоти поруч із макетами, список розбіжностей порожній або пояснений
- [ ] i18n, токени, a11y (aria-label для іконкових кнопок, тап ≥ 44)
- [ ] звіт за `/verify`
